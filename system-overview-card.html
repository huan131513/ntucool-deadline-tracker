系統運作說明 · ntucool-deadline-tracker

從 Chrome 登入狀態
到手機上的一則截止提醒

系統不存密碼、不呼叫爬蟲——每一步都走 Canvas 官方 /api/v1/ 端點,認證來源是你本機 Chrome 裡「當下」的登入狀態。以下是它每小時整點在背景做的事,以及使用上該注意的地方。

Trigger · launchd StartInterval
每小時整點觸發一次
一天執行 24 次,取代「偵測登入瞬間」——反正每次都即時讀當下 session, 間隔一小時就等於「你登入後最慢 1 小時內會被抓到」,不需要額外常駐服務或瀏覽器書籤。
你在 Chrome 保持登入 NTUCOOL 前提條件
不用刻意每天登入——只要 session cookie 還活著,平常瀏覽網頁就會延續它。這是整套系統唯一需要「人」介入的環節。
launchd 準時喚醒 main.py 每小時 · :00
macOS 排程服務,比 cron 更能配合電腦睡眠/喚醒。執行結果寫進 launchd.log 方便回頭查。
讀取 Chrome cookie,打官方 Canvas API GET /api/v1/…
用 browser_cookie3 即時從本機 Chrome 讀 session,依序打 /courses 與每門課的 /assignments,全程不儲存密碼。
比對截止日門檻,查重複記錄 7 / 3 / 1 天
剩餘天數落入門檻,且 state.json 裡還沒發過,才會進到下一步——同一個門檻只提醒一次,不會因為每小時跑而洗版。
Telegram Bot 發出提醒 課程 · 作業 · 截止時間
訊息內容含課程名稱、作業名稱、截止時間與剩餘天數,直接送到你手機上的 Telegram 對話。

使用上要注意的五件事

這些不是理論上的邊界情況,是實際測試時就會遇到的限制。

只能在這台 Mac 本機跑
認證靠讀取本機 Chrome 的 cookie 存放區,無法部署到 Vercel 等雲端服務——那裡碰不到你的瀏覽器資料。
Mac 睡眠時排程會被跳過
跳過的那次不會補跑,下次開機後要等到下一個整點才會再執行。
只認正式的 Canvas「作業」
老師寫在公告、Syllabus、Pages 文字裡的截止日不是結構化資料,系統抓不到,只有掛在「作業」分頁下的才算。
cookie 失效時不會發假通知
遇到 401/419 會直接報錯提示「請重新登入」,而不是安靜失敗或送出錯誤資訊。
cookie 的敏感度等同密碼
config.json 已加入 .gitignore,但這串值本身足以冒用你的登入狀態,不要貼到任何地方。
